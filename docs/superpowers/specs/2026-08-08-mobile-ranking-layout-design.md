# 手机端长排名布局修复设计

## 背景

大学目录在宽度不超过 800px 时使用三列网格：大学名称占第一列，QS 与 THE 排名各占一个 `auto` 列。排名值较短的学校（例如帝国理工学院）显示正常，但 `1001–1200`、`601–800` 等长区间会把两个 `auto` 列撑宽，继而把名称列压缩到只剩一个汉字或几个英文字母的宽度。

## 已批准方案

仅调整手机端卡片内部排版，桌面端完全不变。

- 第一行只承载大学名称和中国规则状态。
- QS 2027 与 THE 2026 放入共同的排名容器，移动端由该容器独占下一行。
- 排名胶囊在可用宽度内并排；屏幕更窄时允许自然换行。
- 现有院校名称、状态、范围、来源、折叠名单、排序和搜索行为均不改变。
- 桌面端继续把 QS 与 THE 分别放在现有第 2、3 列，保持六信息组布局。

## 结构

在 `src/pages/index.astro` 中为现有两个排名节点增加 `.ranking-pills` 父容器。桌面端父容器使用 `display: contents`，因此两个排名节点仍直接参与原六列网格；移动端父容器改为完整占据卡片下一行的 flex 容器。

手机端 `.university-row` 改为两列：`minmax(0, 1fr) auto`。名称使用第一列，状态使用第二列，排名容器跨越全部列。这样长排名只会在自己的行内换行，不会参与名称行的列宽计算。

在宽度不超过 430px 时，状态继续按现有视觉移到独立一行，排名容器顺延到下一行。专业院校说明随后顺延，避免与排名重叠。

## 回归保护

- 页面结构测试确认两个排名节点被 `.ranking-pills` 包裹。
- CSS 契约测试确认桌面端 `.ranking-pills{display:contents}`，保留 `.rank-qs` 与 `.rank-the` 的第 2、3 列。
- CSS 契约测试确认移动端使用两列名称/状态网格，排名容器跨越全宽、允许换行，并删除会把名称压窄的三列移动规则。
- 构建后使用浏览器检查 390px 手机视口中的伦敦都市大学和帝国理工学院，同时检查桌面视口的六列对齐未变化。

## 非目标

- 不修改任何院校、排名或中国院校规则数据。
- 不修改每日来源审查、搜索、筛选、排序或发布逻辑。
- 不重新设计桌面端，也不改变排名文字、字体或胶囊样式。
