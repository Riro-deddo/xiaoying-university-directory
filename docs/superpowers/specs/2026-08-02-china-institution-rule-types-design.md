# 中国院校规则类型与折叠展示设计

## 目标

“小英高校百科”必须按中国申请者实际理解区分院校准入限制与成绩分档，不能把大学官网上任何含中国院校名称的页面都笼统称为 List。

页面总体结构、英国大学目录、双向搜索、免费静态部署和每日自动检查保持不变。此次改动只修正来源语义、证据文案和折叠内容。

## 用户问题

中国学生通常把“院校 List”理解为本科院校背景会影响能否申请某所英国大学或某些专业。大学官网实际上至少存在三种不同规则：

1. 院校准入限制：名单成员身份决定某个范围内是否接受申请。
2. 院校分档与成绩门槛：名单或 Tier 决定最低均分，但名单外不一定不能申请。
3. 普通中国申请要求：页面没有列出中国本科院校，也没有院校成员关系可供查询。

如果不区分这三类，用户可能把“需要更高均分”误读为“不能申请”，或把学院的一般要求误读为学院 List。

## 已核对来源的分类

| 来源 | 规则类型 | 名单外含义 | 展示决定 |
| --- | --- | --- | --- |
| UCL 中国研究生要求 | 院校分档与成绩门槛 | 其他获中国教育部认可的院校仍可按更高均分门槛申请 | 显示折叠院校表，并同时展示名单内外门槛 |
| 爱丁堡 Priority List | 混合规则 | Band A/B 项目要求 Priority List；Band C/D 对名单外认可院校存在不同规则 | 显示折叠 Priority List，并强调最终取决于课程 Band |
| 南安普顿 Tier 名单 | 院校分档与成绩门槛 | 未列出的院校按 Tier D 门槛处理 | 保持官网直达链接；安全结构化完成前不复制本地表 |
| 曼彻斯特大学法学院中国要求 | 普通学院要求 | 官网未提供中国本科院校名单 | 保留学院范围和官网入口，不生成 List |

以上分类只描述已核对的当前官网规则。大学或课程更新后，分类也必须重新核验。

## 数据模型

每个官方来源增加人工核验的 `institutionRule` 元数据：

```ts
interface InstitutionRule {
  type: 'eligibility' | 'grade-threshold' | 'mixed' | 'none';
  summaryZh: string;
  listedMeaningZh?: string;
  unlistedMeaningZh?: string;
  caveatZh?: string;
}
```

- `eligibility`：院校成员身份明确影响指定范围内能否申请。
- `grade-threshold`：院校成员身份或 Tier 只决定成绩门槛。
- `mixed`：不同课程或 Band 同时包含准入与成绩门槛规则。
- `none`：来源没有中国本科院校成员表。

这些字段是对大学官方规则含义的简短人工核验，不由抓取器自行推断。`RequirementFact` 仍保存院校行、大学官方分组和分数事实，不复制第二份名单。

## 目录与折叠展示

目录布局保持不变，但“公开院校 List”这类容易误导的统一标签改为“有中国院校规则”。每个来源在卡片中显示明确规则标签：

- 院校准入限制
- 院校成绩分档
- 准入与成绩混合规则
- 未发现院校名单

只有同时满足以下条件的来源才生成折叠院校表：

1. `institutionRule.type` 不是 `none`；
2. 已通过解析保护条件；
3. 已生成结构化院校事实；
4. 来源范围、周期和名单含义均可显示。

折叠标题根据类型变化，不再统一写“已收录院校 List”：

- 准入限制：`查看官方院校准入名单（N 所）`
- 成绩分档：`查看官方院校成绩分档（N 所）`
- 混合规则：`查看官方 Priority List（N 所）`

折叠内容顶部先显示 `summaryZh`、名单内含义、名单外含义、适用范围、申请季、最近提取时间和官网链接，再显示院校行。名单外含义必须在院校行之前可见。

学院或专业范围的来源使用完全相同的折叠组件，但必须醒目标明“仅适用于：某学院/专业”。不得把学院规则外推到全校。

`link-only` 来源不生成本地院校表。若规则类型不是 `none`，显示“官网存在院校规则，但本站暂未完成安全结构化”的中性说明和官网直达链接。规则类型为 `none` 的学院要求页面只展示其范围与官网入口，不冒充 List。

## 中国本科院校反向查询

反向查询继续与折叠表共用同一份结构化事实，但证据文案根据规则类型变化：

- `eligibility` 命中：只说明在指定范围的官方准入名单中找到；最终仍需核对课程要求。
- `grade-threshold` 命中：说明在官方成绩分档中找到，并显示分组或最低分。
- `mixed` 命中：说明在 Priority List 中找到，同时提示申请资格取决于课程 Band。
- 未命中：显示来源登记的 `unlistedMeaningZh`，不得自动写成“不能申请”。
- `link-only`：保持中性，不产生院校命中或名单外结论。
- `none`：只说明未发现可查询的院校名单。

UCL 的名单外结果必须明确说明其他教育部认可院校适用更高门槛；爱丁堡的名单外结果必须说明是否接受取决于课程 Band；南安普顿在完成安全结构化之前不得产生本地 Tier 结果。

## 自动更新与错误处理

每日 GitHub Actions、解析数量保护、重复项检查、删除比例保护和异常 Issue 机制保持不变。抓取器只更新院校行事实，不自动修改人工核验的规则类型或名单含义。

当官方页面的规则文字与已登记含义发生明显变化时，自动更新必须拒绝发布并提示人工复核，而不是继续展示旧的准入或成绩解释。

## 测试与验收

必须覆盖：

- UCL 被标记为成绩分档，不显示为准入名单；
- 爱丁堡被标记为混合规则，并显示课程 Band 提示；
- 南安普顿保持 `link-only`，名单外默认 Tier D 的含义可见，但无本地院校行；
- 曼大法学院被标记为 `none`，不生成折叠 List；
- 未来结构化的学院级准入或成绩名单会自动获得带学院范围警示的折叠面板；
- 任何未命中状态都不自动生成“不能申请”；
- UCL 84 行和爱丁堡 81 行仍来自原有结构化事实；
- 320px 宽度下说明和院校行不横向溢出；
- 页面、方法说明和 README 对四种规则类型使用同一套中文表述。

## 非目标

- 不判断录取概率或给学生选校建议。
- 不把大学的 Tier、Band 翻译成中国官方院校等级。
- 不自动总结所有学院网页中的自由文本要求。
- 不在没有结构化院校行时手工复制大名单。
- 不把“名单中找到”简化为“可以申请”，也不把“名单中未找到”简化为“不能申请”。
