# 待确认院校中国规则全量复核设计

## 目标

逐所复核目录中当前标记为“待确认”的 65 所英国大学，优先发现大学或学院官网公开的中国本科院校名单、院校分档和准入限制，同时补齐只有中国学历或成绩要求的学校。复核后，只有证据充足的学校才能离开“待确认”。

本轮不改变 101 所目录范围、QS/THE 排名、特色院校说明、页面结构或既有已核验院校事实。

## 官方证据边界

可接受的证据只有：

- 大学或学院官方网站上的招生、国际学生、国家要求或课程页面；
- 由大学官方域名直接托管或明确链接的 PDF、电子表格和可下载名单；
- 大学官方页面嵌入的第一方国家要求查询器所显示的中国结果。

搜索引擎摘要、留学机构、小红书、论坛、转载文档和未能追溯到校方的名单只能帮助发现线索，不能作为网页事实来源。

## 状态判定

每所学校只能采用下列最具体的状态：

1. `official-list`（有中国院校规则）
   - 官方材料列出具体中国大学名称；或
   - 官方材料提供可确定成员范围的中国院校组别、白名单、分档或准入限制；或
   - 官方材料提供完整可下载名单。
   - 页面显示可折叠 List，并写清名单含义、适用范围、更新时间和官方来源。

2. `faculty-only`（部分学院公开）
   - 只有某个学院、院系或具体课程公开具体中国院校名单或分档；
   - 页面必须在摘要、名单标题和范围中明确学院或课程，不能推断为全校规则。

3. `china-requirements`（中国申请要求）
   - 官方材料给出中国学位、均分、成绩等级或资格等值要求；
   - 可能提到“prestigious”“well-ranked”“recognised”等院校背景因素，但没有公开可确定成员的院校名单或分组；
   - 不展示可折叠 List，不把普通成绩要求包装成院校规则。

4. `not-public`（未发现院校规则）
   - 官方材料明确表示会考虑本科院校背景、存在内部名单或需要招生部门个案确认，但没有公开具体成员；或
   - 官方材料明确表示相关院校名单或分档不对外公开。
   - 摘要必须描述实际证据，不能把“搜索不到”写成“学校没有名单”。

5. `pending`（待确认）
   - 未找到足够的官方中国申请证据；
   - 页面被登录、交互组件、地区限制或持续访问异常阻断；
   - 搜索结果互相冲突，或名单只能从第三方获得。

如果同一学校同时有全校普通要求和学院名单，以 `faculty-only` 为主状态，并同时保留全校中国要求来源。只有全校名单才使用 `official-list`。

## 核查流程

对 65 所学校使用同一流程：

1. 从 `universities.json` 读取官方域名和中英文名称。
2. 使用域名限定检索查找 China、Chinese university list、recognised institution、entry requirements、country requirements、admissions、postgraduate、faculty、school、PDF 等组合。
3. 优先打开最接近招生事实的大学页面，再沿校内链接检查学院页面和下载文件。
4. 对候选页面人工确认发布主体、适用层级、是否包含具体院校成员、申请层次和当前可访问性。
5. 按上述五类状态记录结果。证据不足时保留 `pending`，不为了清空待确认数量而降格认定。
6. 对真正公开的名单提取结构化记录；对普通中国要求只记录摘要和来源。

自动化只负责生成候选链接、去重和格式校验；状态判断与名单语义必须基于官方页面内容。这样减少重复人工搜索，同时避免自动误判。

## 数据写入

确认结果沿用现有数据模型：

- `src/data/universities.json`：更新状态、`sourceIds` 和必要的中性说明；
- `src/data/sources.json`：新增官方页面或第一方文件来源，并标注适用范围；
- `src/data/china-rule-audit.json`：记录 65 所的复核结论、证据范围和 `reviewStatus`；既有已核验记录为 `reviewed`，尚未开始的记录为 `unreviewed`，完成检索但因访问受阻、证据冲突或只有第三方线索而仍保留 `pending` 的记录为 `blocked`；
- `src/data/requirements.json` 与 `src/data/institutions.json`：只为真正公开并能可靠转录的名单增加规则和中国院校记录；
- `src/data/status.json`：为新来源建立每日审查基线；
- `src/data/generated/reverse-index.json` 与 `public/generated/**`：只通过现有构建脚本生成，不手工编辑。

若官方名单只提供图片、扫描 PDF 或无法可靠提取的交互表格，可以先将学校更新为相应状态并提供官方入口，但不得伪造不完整的折叠名单。摘要要明确“官方名单入口已确认，结构化名单尚未录入”。

## 每日审查与变更安全

所有新增官方来源都加入现有每日来源审查。日检只请求已登记链接并记录内容变化、跳转或访问异常：

- 不自动改写大学状态、摘要、名单或成绩要求；
- 页面变化继续显示为待审核 observation；
- 只有人工确认并运行受保护同步后，才能接受新内容哈希和解析事实；
- 单次或短期网络失败不立即把公开来源改成不可用。

## 测试与验证

实施必须先增加失败测试，再写数据：

- 65 所原待确认学校均有明确审计结果，`reviewStatus` 不再是 `unreviewed`，审计集合无遗漏、无重复；
- 所有离开 `pending` 的学校至少有一个同校官方来源；
- `official-list` 与 `faculty-only` 的结构化名单规则具有明确适用范围和来源；
- `china-requirements` 与 `not-public` 不得凭空生成名单记录；
- 新来源全部进入状态审查，并使用 HTTPS 官方域名或可验证的第一方托管地址；
- 已核验的 36 所非待确认学校及其既有规则保持事实不变；
- 目录仍为 101 所，93 所 QS 目录院校和 8 所特色院校的分类不变；
- 全量测试、生产构建、初始 HTML 守卫和 `git diff --check` 必须通过；
- 浏览器复核至少覆盖一个全校名单、一个学院名单、一个普通中国要求、一个未公开规则和一个仍待确认案例，检查搜索、筛选、折叠名单、来源链接、控制台和移动端溢出。

## 成功标准

- 65 所学校全部完成一次可追溯的官方来源复核；
- 页面上“待确认”的数量只保留真实证据不足或访问受阻的学校；
- 所有新增 List 都能回答“哪些中国本科院校受到怎样的规则约束”，且不会把普通均分要求误称为院校名单；
- 用户可以从每条摘要或折叠名单直接进入对应大学或学院官方来源；
- 每日审查继续自动运行，但不会未经人工确认覆盖已接受事实。

## 非目标

- 不采纳第三方整理名单作为事实来源；
- 不推断未公开的内部名单；
- 不因为本轮复核而扩展目录院校范围；
- 不修改综合排名、专业实力排名或页面视觉设计；
- 不承诺一次性结构化所有无法可靠提取的扫描件和交互式名单。
