# 小英高校百科：101 所英国大学完整硕士专业一览设计

日期：2026-08-11
状态：已确认，待用户复核书面规格

## 1. 目标

在保留现有“中国院校要求”、排名、官方来源、每日巡查和移动端体验的前提下，新增独立的“硕士专业一览”。最终公开版本覆盖现有目录中的 101 所英国大学，以及每所大学当前公开招生且符合范围的全部硕士学位课程。

专业记录不得只做代表性抽样。每个公开专业必须达到统一的完整字段标准，并链接到大学官方课程页面。项目继续使用 GitHub Pages 与 GitHub Actions，不依赖付费数据库、付费 API 或个人电脑常开。

## 2. 收录范围

### 2.1 收录

- 授课型硕士，包括 MSc、MA、LLM、MBA、MPH、MEd、MArch 等硕士学位。
- 研究型硕士，包括 MRes、MPhil、MLitt 等硕士学位。
- 全日制、非全日制、线上、远程及混合学习形式。
- 同一官方课程同时提供多种学习形式时只保留一个专业记录，在该记录内列出所有形式、学制、校区和开学时间。

### 2.2 排除

- PhD 及其他博士学位。
- PGCert、PGDip、Pre-Master、短期课程、CPD 和非学位培训。
- 仅供内部员工、封闭合作项目或不接受直接申请的非公开课程。

课程是否收录以大学当前官方课程目录和课程页面为准。课程名称相同但要求或授予学位不同则保留独立记录；只是学习形式不同则合并为同一记录的不同形式。

## 3. 产品命名和模块边界

顶部导航使用：

`中国院校要求｜硕士专业一览｜使用说明`

- “中国院校要求”继续负责英国大学对中国本科院校的 List、分档、成绩要求和官方来源。
- “硕士专业一览”负责大学、学院、专业方向、硕士课程和通用课程要求。
- 中国规则状态不出现在硕士专业列表中。
- 仅当用户主动输入本科院校、平均成绩和本科专业时，系统才把现有中国院校要求与具体专业要求组合为个人匹配说明。
- 模块之间通过稳定大学 ID、学院或专业范围和来源范围关联，不复制规则事实。

## 4. 选定架构

采用按大学拆分的静态数据库，继续部署在 GitHub Pages。

### 4.1 数据分片

- 一个轻量总索引保存 101 所大学、大学别名、专业数量、学院或方向数量和分片路径。
- 每所大学拥有独立专业数据分片。
- 全局搜索使用独立的紧凑搜索索引，只保存搜索所需字段和目标网址。
- 专业详情使用独立静态网址，支持直接分享和搜索引擎收录。
- 来源状态与已接受的专业事实分离，避免巡查时间变化重写课程内容。

### 4.2 加载和更新

- 初始页面只加载大学总索引。
- 用户展开大学时才加载该校分片。
- 搜索可以直接命中专业并打开独立详情页。
- 更新某所大学只重建该校分片、受影响的搜索索引和详情页。
- 不采用包含全部专业的单一大 JSON，也不引入外部数据库或运行时 API。

## 5. 严格折叠与页面结构

页面采用四层结构：

1. **大学层**：默认显示 101 行大学概览，包括大学中英文名称、专业数量、学院或方向数量和展开入口。默认一次只展开一所大学。
2. **学院或方向层**：展开大学后显示学院或规范化专业方向及数量。默认一次只展开一个分组。
3. **专业简表层**：只显示中英文名称、学位类型、可用学习形式和详情入口，不显示完整要求。
4. **独立专业详情页**：展示全部字段、来源、时间和个性化匹配结果。

桌面端和移动端保持相同层级。移动端使用纵向钻取，不横向压缩多列要求，也不出现单字竖排。折叠控件必须使用可访问的原生交互，并保持键盘操作、焦点状态和展开语义。

## 6. 专业记录完整字段

每个专业记录必须包含：

- 稳定专业 ID 和规范网址 slug。
- 中文名称和官方英文名称。
- 大学、学院或学部、规范化专业方向。
- 学位类型。
- 全日制、非全日制、线上、远程或混合等学习形式。
- 各形式的学制、校区、开学月份及当前招生状态。
- 通用学术成绩要求。
- 本科专业或学科背景要求。
- 工作经验、作品集、面试、GMAT、GRE 或其他附加要求。
- 针对中国申请者的公开要求。
- IELTS 或其他公开语言要求。
- 官方课程网址及其他直接支持字段的官方网址。
- 内容更新时间、最近成功来源检查时间和来源范围。
- 当前、待审核变化、可能停招、已归档或来源暂不可用等生命周期状态。

官网没有单独说明某个字段时，记录为“官网未单独说明”并绑定支持这一结论的页面范围；不得猜测、推导或编造内容。

## 7. 来源与规则合并

每个事实字段必须绑定一个或多个第一方官方来源。来源记录至少包含官方 HTTPS URL、大学 ID、范围、字段类型、核验锚点、已接受时间和最近检查时间。

中国申请要求按以下优先级组合：

`具体专业要求 → 学院要求 → 大学中国申请要求 → 通用课程要求`

更具体来源可以覆盖更宽泛来源，但页面必须说明规则来自专业、学院还是大学。现有中国院校要求继续由原数据集维护；生成专业详情时按稳定 ID 和范围关联，不能把同一规则复制进数百个专业文件。

## 8. 个人匹配

个人匹配至少需要：

- 中国本科院校。
- 本科平均成绩。
- 本科专业或学科方向。

语言成绩可选。系统分别返回院校背景、成绩、本科专业和语言条件的判断与依据。只输入本科院校时，不得把整个专业标为“可能适用”或“可以申请”。系统不作录取承诺，最终要求始终以大学、学院、具体课程页面和招生部门为准。

## 9. 数据进入正式页面的流程

固定流程为：

`官方课程目录 → 课程网址清单 → 结构化提取 → 完整性校验 → 审核确认 → 公开数据`

- 自动程序负责发现、抽取候选字段和比较变化。
- 系统只保存必要字段、核验锚点和页面指纹，不保存整份官网正文。
- 只有所有必填字段均有官方来源或明确“官网未单独说明”记录时，课程才达到发布门槛。
- 中文摘要和已接受事实必须经过审核确认后才能进入公开数据。
- 未达到门槛的大学和课程只能留在内部数据中，不出现在公开“硕士专业一览”。

## 10. 生命周期与异常处理

课程状态包括：

- **当前开放**：官方课程仍存在，信息已审核。
- **待审核变化**：检测到官网变化，继续显示最后一次已确认内容。
- **可能停招**：课程页消失或不再出现在目录中，等待交叉核验。
- **已归档**：人工确认课程停止招生，从当前目录移至历史记录。
- **来源暂不可用**：官网超时、403、429 或服务器异常，保留原数据。

异常规则：

- 单次失败不改变公开内容。
- 连续三次失败才显示来源异常。
- 404 不自动删除课程，必须同时核对大学课程目录。
- 改名课程保留稳定 ID 和旧名称别名，原分享链接继续可用。
- 内容变化只创建一条按来源和变化类型去重的待审核记录。
- 不绕过 robots、登录、验证码、访问限制或学校明确禁止的路径。
- 审核确认后才更新中文摘要和内容更新时间。

## 11. 巡查与长期维护

- 现有中国院校要求来源继续每日检查。
- 101 所大学课程目录每日检查，发现新增、删除或改名候选。
- 单个专业详情分成七组轮换，每周完成一轮。
- 已发生变化、处于待审核或临近申请季的高风险页面每日跟踪。
- 每个新申请季开始时进行一次全量课程普查、差异报告和版本归档。
- GitHub Actions 使用稳定并发、批次隔离、失败阈值和通知去重，避免一个网站失败导致全部巡查失败。

## 12. 建设与发布策略

项目内部按批次建设，但公开入口只在 101 所全部完成后启用：

1. **课程普查**：确认每所大学的课程目录、符合范围的课程数量、网站结构和访问限制。
2. **基础架构**：建立数据 schema、分片、搜索索引、四层页面和专业详情路由。
3. **大学批次**：逐校完成全部课程并通过该校完整性校验。
4. **个人匹配**：接入现有中国院校要求、成绩和本科背景判断。
5. **巡查系统**：实现目录每日、详情每周和高风险每日检查。
6. **最终 QA**：完成全量数据、性能、SEO、桌面和移动端验收后一次性启用入口。

在公开入口启用前，现有线上网站和现有功能保持不变。

## 13. 自动测试与质量门槛

测试必须覆盖：

- 101 所大学均有官方课程目录来源或明确无符合范围课程的记录。
- 每所大学已收录集合与其审核时点的官方目录一致。
- 全部大学、专业 ID、canonical URL 和详情页网址唯一。
- 收录和排除的学位类型符合本设计。
- 同一专业不同学习形式正确合并，要求实质不同的课程保持独立。
- 所有必填字段有来源或明确未说明状态。
- 专业级、学院级、大学级和通用规则优先级正确。
- 个人匹配不会只凭本科院校产生整体适用结论。
- 搜索、折叠、按需加载、深链接和无 JavaScript 基础可读性可用。
- 移动端无横向溢出、单字竖排、控件重叠或不可读详情。
- 首页不会一次加载数千条课程。
- 404、限流、连续失败和内容变化不会覆盖已接受摘要。
- 现有中国院校要求、排名、来源巡查和部署流程无回归。

## 14. 最终上线门槛

启用“硕士专业一览”必须同时满足：

- 101 所大学全部完成课程普查。
- 所有符合范围的当前硕士课程均已收录。
- 每条课程达到完整字段和来源标准。
- 没有未处理的高风险数据异常。
- 搜索索引、分片、详情页和 sitemap 全部生成成功。
- 自动测试、生产构建、桌面端和移动端验收通过。
- 每个专业拥有稳定、可分享、可被搜索引擎收录的独立网址和官方来源。

## 15. 工作量和第一步

完整建设预计为数千条课程记录和数十种官网结构，属于多阶段项目，不能在单次 Token 周期内完成。正式排期前先执行只读课程普查，得到真实课程总数、可复用网站模板和需要单独适配的大学列表。课程普查不改变线上网页，也不产生正式中文摘要。

课程普查完成后再给出可验证的时间、Token 和维护成本估算，并据此拆分后续实现计划。
